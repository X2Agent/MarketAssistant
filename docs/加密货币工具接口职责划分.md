# 加密货币工具接口职责划分

## 概览

本文档说明MarketAssistant中各个加密货币工具接口的职责划分，确保单一职责原则，避免功能重复。

## 接口职责矩阵

| 接口 | 职责 | 数据源 | 方法数量 |
|------|------|--------|----------|
| **ICryptoBasicTools** | 基础行情和项目信息 | 币安 + CoinDesk | 2 |
| **ICryptoMetricsTools** | 市场深度数据和综合指标 | 币安 + CoinGecko | 6 |
| **ICryptoSentimentTools** | 市场情绪和衍生品指标 | 币安期货 | 5 |
| **ITechnicalDataTools** | 技术指标计算 | 计算 | 4 |

---

## 1. ICryptoBasicTools - 基础数据工具

### 职责
提供**最基本的行情数据和项目基本面信息**，是其他工具的基础。

### 数据源
- **币安API**: 24小时行情数据
- **CoinDesk API**: 项目基本面信息

### 方法列表

1. `GetAssetInfoAsync(string assetSymbol)` → `CryptoQuoteInfo`   - 获取24小时行情（价格、涨跌幅、成交量等）   - 数据源：币安 `/api/v3/ticker/24hr`

2. `GetProjectInfoAsync(string assetSymbol)` → `CryptoProjectInfo`
   - 获取项目基本面（描述、供应量、市值、排名等）
   - 数据源：CoinDesk `/asset/v2/metadata`

### 使用场景
- 快速查询币种当前价格和涨跌情况
- 了解币种基本面信息（项目描述、代币经济学）
- 作为其他分析的基础数据源

---

## 2. ICryptoMetricsTools - 市场指标工具

### 职责
提供**市场深度数据、综合市场指标和衍生计算指标**，用于深入的市场分析。

### 数据源
- **币安API**: 市场深度数据（K线、订单簿、成交）
- **CoinGecko API**: 综合市场指标（市值、排名、流通率等）
- **计算**: 波动性指标

### 方法列表

#### 市场深度数据（币安）

1. `GetOHLCVAsync(symbol, interval, limit, startTime, endTime)` → `CryptoOHLCV`
   - 获取历史K线数据（OHLCV）
   - 数据源：币安 `/api/v3/klines`
   - 用途：技术分析、回测、趋势判断

2. `GetOrderBookDepthAsync(symbol, limit)` → `CryptoOrderBookDepth`
   - 获取订单簿深度数据
   - 数据源：币安 `/api/v3/depth`
   - 用途：分析流动性、支撑压力位、买卖价差

3. `GetRecentTradesAsync(symbol, limit)` → `CryptoRecentTrades`
   - 获取最近成交数据
   - 数据源：币安 `/api/v3/trades`
   - 用途：分析买卖力量对比、成交活跃度

#### 综合市场指标（CoinGecko）

4. `GetMarketMetricsAsync(symbol)` → `CryptoMarketMetrics`
   - 获取综合市场指标（市值、供应量、排名、流通率等数值指标）
   - 数据源：CoinGecko `/coins/markets`
   - 用途：资产估值、市值分析
   - **注意**: 与`ICryptoBasicTools.GetProjectInfoAsync`的区别是，本方法侧重数值型市场指标，而非描述性信息

5. `GetVolumeDistributionAsync(symbol)` → `List<VolumeDistribution>`
   - 获取交易量在各交易所的分布
   - 数据源：CoinGecko `/coins/{id}/tickers`
   - 用途：分析流动性分布、选择交易所

#### 衍生计算指标

6. `GetVolatilityMetricsAsync(symbol, days)` → `CryptoVolatilityMetrics`
   - 计算波动性指标（历史波动率、ATR、最大回撤、夏普比率）
   - 数据源：基于历史K线数据计算
   - 用途：风险评估、仓位管理

### 使用场景
- 深度技术分析（K线图表、支撑压力）
- 流动性分析（订单簿、价差）
- 市场趋势研究（成交分布、买卖力量）
- 风险评估（波动率、回撤）
- 资产估值（市值、流通率）

## 3. ICryptoSentimentTools - 市场情绪工具

### 职责
提供**市场情绪和衍生品相关指标**，帮助判断多空力量对比和市场参与度。

### 数据源
- **币安期货API**: 所有数据均来自期货市场

### 方法列表

1. `GetFundingRateAsync(symbol)` → `FundingRateHistory`
   - 获取资金费率历史数据
   - 数据源：币安 `/fapi/v1/fundingRate` + `/fapi/v1/premiumIndex`
   - 用途：判断市场多空情绪（正值=看多，负值=看空）

2. `GetGlobalLongShortRatioAsync(symbol, period, limit)` → `LongShortRatioHistory`
   - 获取全局账户多空比
   - 数据源：币安 `/futures/data/globalLongShortAccountRatio`
   - 用途：了解全市场散户情绪

3. `GetTopTraderAccountRatioAsync(symbol, period, limit)` → `LongShortRatioHistory`
   - 获取顶级交易员账户多空比
   - 数据源：币安 `/futures/data/topLongShortAccountRatio`
   - 用途：了解大户账户数量分布

4. `GetTopTraderPositionRatioAsync(symbol, period, limit)` → `LongShortRatioHistory`
   - 获取顶级交易员持仓多空比
   - 数据源：币安 `/futures/data/topLongShortPositionRatio`
   - 用途：了解大户资金分布（更准确）

5. `GetOpenInterestAsync(symbol, period)` → `OpenInterest`
   - 获取未平仓合约量
   - 数据源：币安 `/futures/data/openInterestHist`
   - 用途：判断市场参与度、杠杆风险

### 使用场景
- 市场情绪分析（资金费率、多空比）
- 大户行为追踪（顶级交易员数据）
- 杠杆风险评估（未平仓合约量）
- 趋势确认（持仓量与价格关系）

## 4. ITechnicalDataTools - 技术指标工具

### 职责
提供**常用技术指标计算**，支持技术分析。

### 数据源
- **计算**: 基于历史价格数据计算各种技术指标

### 方法列表

1. `GetKDJAsync(assetSymbol)` → `TechnicalKDJ`   - KDJ随机指标

2. `GetMACDAsync(assetSymbol)` → `TechnicalMACD`
   - MACD指标（移动平均收敛散度）

3. `GetBOLLAsync(assetSymbol)` → `TechnicalBoll`
   - 布林带指标

4. `GetMAAsync(assetSymbol)` → `TechnicalMA`
   - 移动平均线（MA）

### 使用场景
- 技术分析
- 买卖信号判断
- 趋势和震荡识别

## 数据获取原则

### 单一数据源原则
每个API端点只由一个接口的一个方法负责调用，避免重复实现。

### 明确职责分工

| 数据类型 | 负责接口 | 数据源 |
|---------|---------|--------|
| 24小时行情 | ICryptoBasicTools | 币安 Spot API |
| 项目描述信息 | ICryptoBasicTools | CoinDesk API |
| K线历史数据 | ICryptoMetricsTools | 币安 Spot API |
| 订单簿深度 | ICryptoMetricsTools | 币安 Spot API |
| 最近成交 | ICryptoMetricsTools | 币安 Spot API |
| 综合市场指标 | ICryptoMetricsTools | CoinGecko API |
| 交易量分布 | ICryptoMetricsTools | CoinGecko API |
| 波动性指标 | ICryptoMetricsTools | 计算 |
| 资金费率 | ICryptoSentimentTools | 币安期货 API |
| 多空比 | ICryptoSentimentTools | 币安期货 API |
| 未平仓合约量 | ICryptoSentimentTools | 币安期货 API |
| 技术指标 | ITechnicalDataTools | 计算 |

### 无Fallback机制
- 每个方法使用固定的数据源，不实现API fallback
- 如果主数据源失败，直接抛出异常
- 保持代码简单清晰，易于维护

## 常见问题 (FAQ)

### Q1: 为什么GetAssetInfoAsync和Get24hrTickerAsync返回不同的模型？
**A**: 因为它们属于不同的接口：
- `ICryptoBasicTools.GetAssetInfoAsync` 返回 `CryptoQuoteInfo` - 适配统一的报价接口
- 之前的 `ICryptoMetricsTools.Get24hrTickerAsync` 已移除，避免重复

### Q2: GetProjectInfoAsync和GetMarketMetricsAsync有什么区别？
**A**: 职责不同：
- `ICryptoBasicTools.GetProjectInfoAsync` (CoinDesk): **描述性信息** - 项目描述、行业分类、安全审计等
- `ICryptoMetricsTools.GetMarketMetricsAsync` (CoinGecko): **数值型指标** - 市值、排名、流通率、历史高低点等

### Q3: 为什么ICryptoMetricsTools不包含资金费率和持仓量？
**A**: 因为这些是**期货市场情绪数据**，属于`ICryptoSentimentTools`的职责范围。`ICryptoMetricsTools`专注于现货市场的深度数据和综合指标。

### Q4: 如果币安API失败了，会尝试其他数据源吗？
**A**: **不会**。每个方法使用固定的数据源，失败直接抛出异常。这样设计的好处是：
- 代码简单清晰
- 职责明确
- 易于维护
- 问题容易定位

### Q5: 为什么不实现链上数据和DEX数据？
**A**: 这些功能在接口中已定义但在实现中被移除，原因是：
- 需要专门的付费API（如CoinDesk Address Metadata、GeckoTerminal Pro）
- 数据更新频率低，实时性要求不高
- 如果确实需要，可以单独实现并明确标注需要付费API

### Q6: Playwright爬虫什么时候使用？
**A**: **暂不考虑**。只有在以下情况才会考虑：
- 指标非常重要且无替代方案
- 所有API都不提供该数据
- 用户明确要求

## 使用示例

### 场景1: 快速查看币种行情

```csharp
// 使用ICryptoBasicTools获取基础行情
var basicTools = serviceProvider.GetRequiredService<ICryptoBasicTools>();
var quote = await basicTools.GetAssetInfoAsync("BTC");
Console.WriteLine($"BTC当前价: ${quote.CurrentPrice}, 涨跌: {quote.PercentageChange}%");
```

### 场景2: 深入技术分析

```csharp
// 使用ICryptoMetricsTools获取K线和深度数据
var metricsTools = serviceProvider.GetRequiredService<ICryptoMetricsTools>();

// 获取30天K线
var ohlcv = await metricsTools.GetOHLCVAsync("BTCUSDT", "1d", 30);

// 获取订单簿深度
var depth = await metricsTools.GetOrderBookDepthAsync("BTCUSDT", 100);
Console.WriteLine($"买卖价差: ${depth.Spread} ({depth.SpreadPercent:F2}%)");
```

### 场景3: 市场情绪分析

```csharp
// 使用ICryptoSentimentTools分析市场情绪
var sentimentTools = serviceProvider.GetRequiredService<ICryptoSentimentTools>();

// 资金费率判断多空情绪
var fundingRate = await sentimentTools.GetFundingRateAsync("BTCUSDT");
if (fundingRate.CurrentRate > 0.1m)
    Console.WriteLine("市场极度看多");
    
// 未平仓合约量判断参与度
var openInterest = await sentimentTools.GetOpenInterestAsync("BTCUSDT", Period.OneHour);
Console.WriteLine($"当前持仓: {openInterest.CurrentOpenInterest} BTC");
```

### 场景4: 风险评估

```csharp
// 组合使用多个工具进行全面风险评估
var basicTools = serviceProvider.GetRequiredService<ICryptoBasicTools>();
var metricsTools = serviceProvider.GetRequiredService<ICryptoMetricsTools>();
var sentimentTools = serviceProvider.GetRequiredService<ICryptoSentimentTools>();

// 1. 基础数据
var quote = await basicTools.GetAssetInfoAsync("BTC");

// 2. 波动性指标
var volatility = await metricsTools.GetVolatilityMetricsAsync("BTCUSDT", 30);

// 3. 市场深度
var depth = await metricsTools.GetOrderBookDepthAsync("BTCUSDT", 100);

// 4. 市场情绪
var fundingRate = await sentimentTools.GetFundingRateAsync("BTCUSDT");

// 综合风险评分
var riskScore = CalculateRiskScore(volatility, depth, fundingRate);
Console.WriteLine($"风险评分: {riskScore}/100");
```

## 总结

通过明确的职责划分：
- ✅ **避免功能重复** - 每个API端点只有一个方法调用
- ✅ **单一职责** - 每个接口专注于特定领域
- ✅ **易于维护** - 职责清晰，修改影响范围小
- ✅ **代码简洁** - 无fallback逻辑，直接明了
- ✅ **便于扩展** - 新增功能时职责归属清晰

这种设计确保了代码的可维护性和可扩展性，为财务分析师提供了清晰、专业的数据获取接口。
