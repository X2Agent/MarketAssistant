# ReAct模式功能说明

## 概述

MarketChatSession对话系统**默认启用ReAct（Reasoning and Acting）模式**，通过"思考-行动-观察"循环自主处理复杂的市场分析任务。

## 重大变更（2026-01-09）

### v3.0 基于Cline范式深度优化

在 v2.0 基础上，参考 [Cline AI编码助手](https://zhuanlan.zhihu.com/p/1902145418839725370) 的严格标准进一步优化：

#### 核心改进

1. **强化思考质量要求** - Thought必须明确回答5个问题：
   - 已有信息：当前掌握了哪些数据？
   - 缺失信息：还需要什么关键信息？
   - 工具选择：为什么选择这个工具而非其他？
   - 参数准备：工具所需参数是否齐全？
   - 逻辑连贯：这一步如何推进问题解决？

2. **禁止冗余表达** - 严格执行中文场景规则：
   - 禁止使用："好的"、"当然"、"没问题"、"明白了"、"让我来"
   - 要求直接进入主题："分析..."、"获取..."、"筛选..."
   - 自动检测并引导AI改正

3. **Final Answer质量标准** - 严格执行完整性要求：
   - 必须完整、最终、不需要用户进一步输入
   - 严禁以问句结尾（如"还需要什么帮助？"、"有其他问题吗？"）
   - 应以明确结论或风险提示结尾
   - 自动检测并修正违规问句

4. **增强格式验证** - 更严格的质量控制：
   - 检测冗余开场白并强制改正
   - 验证Thought质量（不仅检查存在性）
   - 识别并移除Final Answer中的问句
   - 连续违规时终止对话并要求重新提问

### v2.0 重构优化（基线）

基于 [Cursor Agent Prompt 2.0](https://github.com/x1xhlol/system-prompts-and-models-of-ai-tools/blob/main/Cursor%20Prompts/Agent%20Prompt%202.0.txt)：

1. **默认启用ReAct** - 移除 `enableReActMode` 参数
2. **优化系统提示词** - 更清晰的指令结构
3. **增强错误处理** - 改进异常恢复机制
4. **提高迭代上限** - 从10次提升到15次
5. **改进响应验证** - 更智能的格式检测

### 2. ReAct模式（默认启用）

#### 使用方式

```csharp
// ReAct模式已默认启用，无需额外配置
var session = new MarketChatSession(
    chatClient, 
    logger, 
    mcpService, 
    initialStockCode: "000001"  // 可选的初始股票代码
);

// 直接使用，系统自动使用ReAct循环
var response = await session.SendMessageAsync("分析比亚迪近期表现");
```

#### 核心改进

**1. 更智能的系统提示词**
- 明确的能力说明（技术分析、基本面分析、风险提示）
- 详细的ReAct循环步骤（Thought → Action → Observation → 循环/结束）
- 严格的格式要求和丰富的示例
- 工具使用指南（何时使用哪个工具）

**2. 增强的错误处理**
- 空响应自动重试机制
- 格式不规范时智能引导
- 异常情况下优雅降级
- 详细的日志记录和调试信息

**3. 优化的迭代逻辑**
- 最大迭代次数：15次（原10次）
- 智能检测Thought+Action组合
- 自动识别最终答案标记
- 超时保护返回已有分析结果

#### 工作流程

ReAct模式使用以下循环处理复杂问题：

1. **Thought（思考）** - AI分析当前问题，规划下一步行动
2. **Action（行动）** - 调用工具获取信息或执行操作
3. **Observation（观察）** - 分析工具返回的结果
4. 重复步骤1-3，直到得出最终答案

#### 响应格式

AI在ReAct模式下会使用特定格式（v3.0强化质量标准）：

```
Thought: [详细思考，必须包含：已有信息+缺失信息+工具选择理由+参数准备+逻辑连贯性]
Action: [调用特定工具和参数]

Observation: [工具返回的数据]

Thought: [基于观察结果的新思考，继续5要素分析]
Action: [下一步行动]

...

Thought: [总结性思考，确认信息充足]
Final Answer: [完整、最终的答案，禁止以问句结尾]
```

**v3.0质量标准示例**：

✅ **正确的Thought**（包含5要素）:
```
Thought: 【已有信息】用户询问比亚迪002594近期表现
【缺失信息】缺少基本信息（市值、行业）、股价数据、财务指标
【工具选择】选择GetStockBasicInfo获取公司概况和当前股价
【参数准备】股票代码002594已知，参数齐全
【逻辑连贯】先了解基本面，再分析技术面和新闻面
```

❌ **不合格的Thought**（模糊、缺要素）:
```
Thought: 需要获取一些股票信息
```

✅ **正确的开场**（直接进入主题）:
```
分析比亚迪002594近期表现，需要获取基本信息...
```

❌ **错误的开场**（冗余表达）:
```
好的，让我来帮你分析比亚迪的情况...
```

✅ **正确的Final Answer**（完整、不带问句）:
```
Final Answer:
【核心观点】比亚迪当前处于上升趋势...
【风险提示】投资有风险，建议关注政策变化和市场波动。
```

❌ **错误的Final Answer**（问句结尾）:
```
Final Answer:
...以上是我的分析，还需要什么帮助吗？
```

#### 示例

**用户问题**：分析比亚迪(002594)近期表现

```
Thought: 需要获取比亚迪的基本信息和最近的股价数据
Action: GetStockBasicInfo(symbol="002594")

Observation: [返回公司基本信息、市值、行业等]

Thought: 现在需要查看技术指标判断趋势
Action: CalculateMACD(symbol="002594", period=30)

Observation: [返回MACD指标数据]

Thought: 还需要了解最新新闻动态
Action: SearchStockNews(symbol="002594", days=7)

Observation: [返回最近7天的新闻]

Thought: 基于基本信息、技术指标和新闻，可以给出综合分析
Final Answer: 
【综合分析】
- 基本面：...
- 技术面：...
- 新闻面：...
【投资建议】...
【风险提示】...
```

#### 配置参数

- `MaxReActIterations = 15` - 最大迭代次数（v2.0提升）
- `MaxOutputTokens = 2000` - 单次输出限制，避免过长响应
- `Temperature = 0.7` - 保持适度创造性
- 自动检测"Final Answer"、"最终答案"、"最终回答"等多种标记
- 智能管理上下文（保留最近8轮对话）

### 3. 使用建议

#### ReAct模式适用场景（默认）

- ✅ **所有市场分析任务** - 系统自动判断复杂度
- ✅ **简单查询** - 一轮即可完成的任务会快速响应
- ✅ **复杂研究** - 需要多步推理和信息综合的深度分析
- ✅ **投资决策支持** - 结合基本面、技术面、新闻面的全面评估

#### 性能考虑

- ReAct模式智能适应任务复杂度
- 简单任务通常1-3轮即可完成
- 复杂分析可能需要5-10轮推理
- 系统自动优化，无需手动干预
- 建议为复杂分析设置合理超时（30-60秒）

## v3.0 关键改进（基于Cline范式）

### 1. 思考质量强制标准

参考Cline的 `<thinking>` 标签强制要求：
- **5要素必答** - 已有信息、缺失信息、工具选择理由、参数准备、逻辑连贯性
- **格式验证** - 不仅检查Thought存在，更检查内容质量
- **引导改正** - 低质量Thought时自动引导补充

### 2. 沟通规范严格执行

参考Cline禁止"Great"、"Certainly"等规则的中文版：
- **自动检测** - 识别开场白中的"好的"、"当然"、"没问题"等
- **强制改正** - 检测到违规表达时立即引导AI重新回复
- **示例对比** - System Prompt中提供正确/错误示例

### 3. Final Answer完整性保证

参考Cline的"attempt_completion不能是问句"规则：
- **问句检测** - 识别"？"、"还需要"、"有其他问题"等模式
- **自动修正** - 移除常见违规问句（"还需要什么帮助吗？"）
- **质量警告** - 记录违规日志，便于后续优化

### 4. 格式验证升级

- **开场白检测** - 阻止冗余礼貌用语
- **Thought质量** - 要求包含5要素说明
- **Final Answer** - 确保完整性和终结性
- **连续违规** - 多次格式错误时终止并引导用户重新提问

## v2.0 关键改进（基线）

### 1. 系统提示词优化

参考Cursor Agent Prompt 2.0最佳实践：
- **结构化指令** - 明确的能力、步骤、格式、原则
- **丰富示例** - 完整的Thought-Action-Observation流程演示
- **工具映射** - 清晰的场景→工具对应关系
- **格式强制** - 严格要求使用规定格式，减少歧义

### 2. 错误处理升级

- **空响应处理** - 自动重试并引导AI继续
- **格式验证** - 检测Thought/Action组合，不完整时引导
- **异常恢复** - 错误后尝试换方式继续（前3轮），后续优雅降级
- **详细日志** - 每步记录，便于调试和优化

### 3. 性能优化

- **迭代次数** - 从10提升到15，支持更深入分析
- **上下文管理** - 保留8轮历史（原6轮），更好理解用户意图
- **输出限制** - 单次2000 tokens，防止超长响应
- **智能判断** - 简单任务快速完成，复杂任务深入分析
