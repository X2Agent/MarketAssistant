# MarketAssistant 产品路线图 (Roadmap.md)

> **文档版本**: 1.0  
> **创建日期**: 2026-09-18  
> **定位**: 本文档从产品经理视角制定 MarketAssistant 的短期/长期开发方向与优先级，作为排期、资源分配与团队对齐的依据。  
> **审视基准**: 基于代码库 v1.0.0-beta2 实际实现、`docs/design.md` 设计蓝图（v1.2）与近期提交记录（统一告警中心、Agent 工具整合、条件单与指数行情增强）。

---

## 一、现状盘点

### 1.1 已有能力（v1.0.0-beta2）

- **双市场架构**：A 股 + Crypto，基于 `MarketType` Keyed Services 的市场抽象使扩展第三个市场的架构成本很低。
- **AI 多分析师协作**：Fan-Out/Fan-In 工作流，5~6 位分析师 + 协调分析师，评分/评级/目标价结构化输出。
- **AI 选股三模式**：需求驱动 / 新闻驱动 / 快速策略。
- **自主交易（Crypto，实验）**：现货/合约/测试网/Demo 四模式，止损止盈、追踪止损、条件单；统一告警中心（去抖/冷却/限次/落库/风险联动门/确认级交易门）。
- **RAG + MCP**：PDF/DOCX/Markdown 文档向量化检索、查询改写与重排、外部工具扩展（stdio/SSE/StreamableHttp）。
- **跨平台**：Windows/macOS/Linux，深浅主题；K 线图主题化、TopBar 指数行情条、自选股双视图等设计规范已落地（详见 `design.md` 第二章收敛确认表）。

### 1.2 关键短板

1. **A 股无交易闭环**：设计哲学宣称"闭环决策漏斗"，但漏斗最后一环（执行）只有 Crypto 有，A 股用户止步于"看 + 研判"，产品价值折半。
2. **核心护城河未建立**：多分析师、选股、RAG 均属"通用能力 + 提示词"，竞品易模仿；真正稀缺的是数据积累、回测验证、个性化记忆。
3. **无留存钩子**：没有组合持仓管理、没有历史分析复盘对比、没有每日主动推送，用户"用完即走"。
4. **信任缺失**：AI 给出买卖建议但从不验证正确性，用户无从判断"该不该信"。
5. **成本不透明**：多分析师并行意味着一次深度研判消耗可观 Token，但用户看不到消耗，也不知道如何用更便宜的模型达到接近的效果。

## 二、短期目标（1~3 个月，v1.1 / v1.2）

> **主题：把"演示级 Demo"打磨成"可日常使用的工具"**——提高留存与口碑，为长期方向争取时间。体验债（design.md Phase 1 / Phase 2 大部分）已基本清偿，短期重心转向信息密度补缺、成本透明与留存钩子。

> **状态：已完成**（本次落地，见 `docs/design.md` Phase 2.4 与各项目 `AGENTS.md`）。

|---|------|------|-----------|------|
| 1 | **AssetPage 信息密度提升**（design.md Phase 2.4 收尾） | 盘口五档/深度概览、分时明细、指标数值面板；页面内直达"加自选 / AI 研判 / 告警 / 交易"入口 | 标的详情是决策主战场，是设计规范中唯一未落地的密度项 | ✅ 已完成。行情速览（今开/最高/最低/昨收/量额/换手/振幅/量比/PE/PB）、技术指标面板（MA/MACD/BOLL/KDJ）、盘口深度、逐笔成交四区块并行加载，互不阻塞；页面内新增告警直达入口。**偏差**：A 股数据源不提供盘口与逐笔，故这两区块仅 Crypto 落地，A 股改为"行情速览 + 技术指标"组合，并在页面显式说明数据源限制（避免被误判为加载失败） |

| 3 | **稳定性与降级体验** | 分析失败的重试与降级提示、数据源不可用时的明确反馈、慢网络下的骨架屏覆盖 | 稳定性是一切留存的前提 | ✅ 已完成。10 个页面补齐首屏骨架屏；统一 `StateOverlayView` 承载"加载 / 空 / 失败 + 重试"；数据层不再把异常吞成空列表，"无结果"与"数据源不可用"在 UI 上可区分；AssetPage 支持单区块重试 |

## 三、长期目标（6~12 个月+，v2.0 方向）

> **主题：从"AI 分析工具"进化为"有记忆、可验证、全链路的市场工作站"**——构建三道护城河。

### 方向 A：决策闭环补全（A 股交易能力）

- A 股接入**模拟盘 / 纸面交易**（不碰实盘：监管风险高、券商接入重），让 A 股用户的"AI 建议"可以落地验证，闭环漏斗真正成立。
- 组合持仓管理：以模拟盘为基础跟踪"AI 建议组合"的累计表现。

### 方向 B：可验证的 AI（信任护城河，最关键的差异化）

- **策略回测**：AI 选股结果与分析师建议自动回测，报告展示"该策略过去 N 次信号的历史胜率"。
- **分析师绩效追踪**：每位 AI 分析师的历史建议归档打分，用户可见"技术分析师近 30 天准确率 62%"，据此配置分析师权重。
- 这是"AI 附庸"与"AI 原生"的分水岭，也是竞品最难抄的部分（依赖历史数据积累）。
- **数据基础已就位（本次落地）**：`MarketAnalysisReport.AnalystSignals` 在报告生成时从各分析师结构化输出提取评级/操作方向/目标价位，随报告全量落库（`ReportArchiveService.reports.report_json`）；`CoordinatorResult` 补了机器可读的 `TargetPriceValue` 与 `ExpectedChangePercent`。M3 剩余工作：定义回测口径（信号事件、持有期、**对照基准**、样本量下限）与统计页面。基准缺失时"胜率"没有意义，务必先定基准再编码。

### 方向 C：个性化与记忆

- 用户画像 + 持仓记忆：AI 知道用户持有某标的，异动时主动归因到"你的持仓"。
- 分析历史沉淀为向量知识库（复用现有 RAG 基建），实现"结合你上次的观点"式连续研判。

### 方向 D：平台化与生态

- 分析师/数据源插件市场：基于现有 MCP + `[RequiresTools]` 契约体系开放扩展点。
- 多市场扩展验证（港美股/期货），检验 Keyed Services 架构的扩展成本。
- 多窗口/多屏盯盘（design.md Phase 3）、移动端伴侣 App（告警推送是天然手机场景）。

## 四、优先级总览

```
                       影响留存/口碑
                            ▲
   P0 AssetPage 密度收尾    │      P0 策略回测+分析师绩效(6月+)
   P0 Token 成本透明        │      P1 A股模拟盘闭环
   P1 每日简报/导出分享      │      P1 用户记忆/持仓画像
                            │
   ─────────────────────────┼──────────────────────────▶
   短期：可用性             │      长期：护城河           影响长期壁垒
   P2 插件生态（低紧迫）
```

**核心逻辑**：短期不做大功能，把高频路径补缺并建立"每天会打开"的理由；长期压注"可验证的 AI + 决策闭环"——分析能力本身可被模仿，但历史数据积累形成的可信度无法被模仿。

**关键取舍**：

- A 股**实盘**交易不做（监管与券商接入成本高一个量级），用"模拟盘 + 纸面交易"达成同样的闭环验证价值。
- 分析师插件市场优先级放低：生态需要用户基数，否则有市场无商户。
- design.md Phase 3 的策略可视化/紧急避险归入 P2：面向少量 Crypto 交易用户，投入产出比低于面向全量用户的功能。

## 五、里程碑与验收标准

| 里程碑 | 时间 | 交付 | 验收标准 |
|--------|------|------|---------|
| M1 | 1 个月 | AssetPage 盘口/五档 + Token 消耗面板 | design.md Phase 2 全部闭环；一次研判可在 UI 内看到各分析师 Token 消耗 ✅ **已交付**（A 股无盘口数据源，盘口/五档为 Crypto 专属） |
| M2 | 3 个月 | 每日简报 + 导出/分享 + 告警增强 | 自选股用户启动 10 秒内可读当日简报；报告可导出 PDF/图片 |
| M3 | 6 个月 | 策略回测 MVP + 分析师绩效 v1 | AI 选股结果可一键回测；报告含历史信号胜率引用 |
| M4 | 12 个月 | A 股模拟盘闭环 + 用户记忆 | A 股用户可对 AI 建议建模拟仓并跟踪表现；AI 能引用用户历史观点 |

**依赖关系**：M3 回测依赖 M1 的结构化输出与数据积累；M4 记忆依赖既有 RAG 基建；插件生态（方向 D）依赖 M1~M3 建立的用户基数，安排在 12 个月后评估。
