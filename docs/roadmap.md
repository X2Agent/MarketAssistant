## 一、现状盘点

### 1.1 已有能力（v1.0.0-beta2）

- **双市场架构**：A 股 + Crypto，基于 `MarketType` Keyed Services 的市场抽象使扩展第三个市场的架构成本很低。
- **AI 多分析师协作**：Fan-Out/Fan-In 工作流，5~6 位分析师 + 协调分析师，评分/评级/目标价结构化输出。
- **AI 选股三模式**：需求驱动 / 新闻驱动 / 快速策略。
- **自主交易（Crypto，实验）**：现货/合约/测试网/Demo 四模式，止损止盈、追踪止损、条件单；统一告警中心（去抖/冷却/限次/落库/风险联动门/确认级交易门）。
- **用量可见与报告分发**：分析报告按分析师归属展示 Token 用量（输入/输出/调用次数）；报告可导出 Markdown / 分享图 PNG / PDF。货币成本估算已于 2026-10 移除（价格表维护负担高于感知价值），只保留 Token 用量。
- **记忆基建（已具备，未产品化）**：`UserMemoryService`（SQLite 持久化）、`MemoryExtractionService`（从对话抽取记忆）、`LayeredMemoryContextProvider`（分层注入上下文）已构成完整链路，缺的是"持仓感知的主动归因"与"历史观点向量化检索"。
- **RAG + MCP**：PDF/DOCX/Markdown 文档向量化检索、查询改写与重排、外部工具扩展（stdio/SSE/StreamableHttp）。
- **跨平台**：Windows/macOS/Linux，深浅主题；K 线图主题化、TopBar 指数行情条、自选股双视图等设计规范已落地（详见 `design.md` 第二章收敛确认表）。

### 1.2 关键短板

1. **A 股无交易闭环**：设计哲学宣称"闭环决策漏斗"，但漏斗最后一环（执行）只有 Crypto 有，A 股用户止步于"看 + 研判"，产品价值折半。
2. **核心护城河未建立**：多分析师、选股、RAG 均属"通用能力 + 提示词"，竞品易模仿；真正稀缺的是数据积累、回测验证、个性化记忆。
3. **留存钩子仍然薄弱**：每日简报已建立"每天打开一次"的理由（留存钩子 v1），但仍无组合持仓跟踪、无历史分析复盘对比；持仓/组合能力目前只存在于 Crypto 侧（`CryptoPortfolioService`），A 股侧完全缺失。
4. **信任缺失**：AI 给出买卖建议但从不验证正确性，用户无从判断"该不该信"。
5. **LLM 用量可见性不完整**：在线分析的 Token 消耗已按分析师归属展示（报告页 + 进度面板），但每日简报等后台调用只汇总总量、未按调用维度拆分；设置页也无法预览"一次典型分析/简报大概消耗多少 Token"。货币成本估算已主动移除——价格表维护负担与过期风险高于用户感知价值，Token 计数足以支撑开销判断。

## 三、长期目标（6~12 个月+，v2.0 方向）

> **主题：从"AI 分析工具"进化为"有记忆、可验证、全链路的市场工作站"**——构建三道护城河。

### 方向 A：决策闭环补全（A 股交易能力）→ 拆分为 M4a / M4b

**M4a：A 股模拟盘闭环**（真正的难点）

**⚠️ 工作量重新评估（2026-10-05 实测，原 v1.1 的"抽象契约"描述偏乐观）**：
这不是"抽象一层接口"，而是**交易域模型的重定义**。实测耦合规模：

| 耦合类型 | 规模（2026-10-05 实测） | 说明 |
|---------|------------------------|------|
| 交易模式枚举 | **19 文件 / 100+ 引用点** | 原 `CryptoTradingMode` 渗透进 `CacheKeys`、`UserSetting` 持久化字段名、`TradingCredentialStore` 加密文件格式（M4a-1 正将其提升为市场无关的 `TradingMode`） |
| `IExchangeClient` 契约 | 契约层即 Crypto 语义 | `SetLeverageAsync` / `positionSide` / 双向持仓——A 股无杠杆无做空 |
| `TradingEnvironmentService` | 语义绑定 Binance 四模式 | 实盘现货 / 实盘合约 / 合约测试网 / 现货 Demo |
| 执行链路 | 构造签名绑定 `[FromKeyedServices(Crypto)] IExchangeClient` | `TradeExecutor`、`RiskManager`、`OrderStateSyncService`、`CryptoPortfolioService` |
| 风控持久化 | `RiskConfigRepository` 硬编码 `MarketType.Crypto` | 建表与查询均以 Crypto 为唯一市场 |

**拆为三阶段，每阶段独立可交付**：

- **M4a-1 契约去 Crypto 化**（前置，🔄 2026-10-05 已开工）：`TradingMode` 环境语义与交易所品牌解耦
  （枚举数值冻结，保证 `UserSetting.json` 与凭证文件兼容）；`IExchangeClient` 收敛为
  市场无关最小集（杠杆/持仓方向下沉为可选能力）。
- **M4a-2 模拟撮合引擎**：纸面撮合 + 持仓/资金账本。
- **M4a-3 A 股规则层**：T+1 交割、100 股整手、涨跌停不可成交、交易时段与集合竞价、按手数计费。

**明确不做**：A 股实盘（监管 + 券商接入成本高一个量级）。
模拟盘已能验证"AI 建议是否可落地"。

**M4b：组合持仓跟踪**

- 以模拟盘为基础跟踪"AI 建议组合"的累计表现。
- 现状：`CryptoPortfolioService` 已提供 Crypto 侧持仓/收益跟踪（含合约），M4b 需先做市场无关化（与 M4a 共用抽象），再补 A 股组合。

### 方向 B：可验证的 AI（信任护城河，最关键的差异化）

- **策略回测**：AI 选股结果与分析师建议自动回测，报告展示"该策略过去 N 次信号的历史胜率"。
- **分析师绩效追踪**：每位 AI 分析师的历史建议归档打分，用户可见"技术分析师近 30 天准确率 62%"，据此配置分析师权重。
- 这是"AI 附庸"与"AI 原生"的分水岭，也是竞品最难抄的部分（依赖历史数据积累）。
- **数据基础已就位**：`MarketAnalysisReport.AnalystSignals` 在报告生成时从各分析师结构化输出提取评级/操作方向/目标价位/止损/置信度/结论周期，随报告全量落库（`ReportArchiveService` 的 `report_json`，并按市场维度补了可索引的 `market_type`/`rating` 列）；`CoordinatorResult` 补了机器可读的 `TargetPriceValue` 与 `ExpectedChangePercent`。M3 剩余工作：定义回测口径（信号事件、持有期、**对照基准**、样本量下限）与统计页面。基准缺失时"胜率"没有意义，务必先定基准再编码。
- **统计口径已设计（`docs/backtest-metrics.md`）**：信号事件定义、T+1 开盘对齐、持期映射（短 5/中 20/长 60 交易日）、A 股涨跌停不可成交剔除、手续费与滑点、Wilson 置信区间、样本量下限 30、基准（沪深300 全收益 / BTC HODL）与超额收益、分析师绩效（方向准确率/置信度分桶校准/滚动衰减）。M3 编码按该文档第七节顺序实施。
- **冷启动与样本不足降级（v1.1 补充）**：置信度与周期字段自本次上线后才有值，**历史报告不参与置信度分桶与周期口径统计**（`Confidence`/`Horizon` 为 null 的信号只计入方向准确率）；可成交样本 < 30 时只展示原始计数、不展示百分比；报告级 `market_type` 对旧行为 NULL，读取方必须按"未知"处理，**禁止从 `asset_code` 反推市场**。
- **⚠️ 价值空窗期（v1.2 补充）**：信号基建 `2c89dd2` 于 2026-09-24 落地，截至 2026-10-05 仅积累 11 天，
  距样本量下限 30 仍差 2 个数量级。因此 M3 必须分两段交付：
  **M3-1 编码期**（可立即开工：回测引擎 + 统计页 + "样本积累中"空态）与
  **M3-2 价值期**（样本达阈值后才展示胜率/校准曲线）。**这不是工程延期，是数据约束，不可通过加班消除。**
  给排期者的提示：M3 的"编码完成"与"用户感知到价值"之间存在数月间隔，不应承诺"6 个月交付可用的胜率展示"。

### 方向 C：个性化与记忆

- **基建已核实到位（v1.2，2026-10-05 对照源码复核）**：`UserMemoryService` / `MemoryExtractionService` /
  `LayeredMemoryContextProvider` 三者已在 `ServiceCollectionExtensions` 注册为单例，
  并由 `MarketChatSessionFactory` 实际注入会话链路——**非空壳代码**，可放心作为前置条件。
  本方向的工作是**产品化**，不是"从零造记忆系统"。
- 用户画像 + 持仓记忆：AI 知道用户持有某标的，异动时主动归因到"你的持仓"（依赖 M4b 的市场无关持仓抽象）。
- 分析历史沉淀为向量知识库（复用现有 RAG 基建），实现"结合你上次的观点"式连续研判。

### 方向 D：平台化与生态

- 分析师/数据源插件市场：基于现有 MCP + `[RequiresTools]` 契约体系开放扩展点。
- 多市场扩展验证（港美股/期货），检验 Keyed Services 架构的扩展成本。
- 多窗口/多屏盯盘（design.md Phase 3）、移动端伴侣 App（告警推送是天然手机场景）。

## 四、优先级总览

```
                       影响留存/口碑
                            ▲
     ┌───────────────────────┴───────────────────────┐
     │  M3-1 回测编码（可立即开工）                   │  M3-2 价值兑现（依赖数据积累）
     │  M4a-1 交易契约去 Crypto 化（进行中）          │  M4a-2/3 模拟撮合+A股规则
     └───────────────────────┬───────────────────────┘
                             │
     ────────────────────────┼───────────────────────▶
   短期：积累                 │         长期：护城河

   ⚠️ 插件生态（方向 D）暂缓：需先有用户基数，否则有市场无商户
```

**核心逻辑**：短期不做大功能，把高频路径补缺并建立"每天会打开"的理由；长期压注"可验证的 AI + 决策闭环"——分析能力本身可被模仿，但历史数据积累形成的可信度无法被模仿。

**关键取舍**：

- A 股**实盘**交易不做（监管与券商接入成本高一个量级），用"模拟盘 + 纸面交易"达成同样的闭环验证价值。
- 分析师插件市场优先级放低：生态需要用户基数，否则有市场无商户。
- design.md Phase 3 的策略可视化/紧急避险归入最低优先级：面向少量 Crypto 交易用户，投入产出比低于面向全量用户的功能。
