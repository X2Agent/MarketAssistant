# 应用图标生成

所有应用图标（exe、窗口、托盘、安装包、各平台打包）都由本目录的脚本从**同一份设计母版**生成。

## 文件职责

| 文件 | 说明 |
|------|------|
| `assets/logo_source.png` | 设计母版，3000×3000 白色背景。**唯一需要手工维护的文件**，不参与任何打包 |
| `scripts/icons/generate_icons.py` | 生成脚本，母版的唯一出口 |

生成产物（`src/MarketAssistant.App/Assets/`）：

| 产物 | 尺寸 | 用途 |
|------|------|------|
| `logo.ico` | 16/20/24/32/40/48/64/96/128/256 | exe 图标、窗口图标、安装包图标 |
| `tray_logo.ico` | 16/20/24/32/48/64 | 系统托盘 |
| `logo_ui.png` | 512×512 | 应用内 UI（导航栏、About 页） |
| `logo_256.png` | 256×256 | Linux deb/rpm 的 hicolor 主题图标 |
| `logo_1024.png` | 1024×1024 | macOS icns 转换源（已排除出 `AvaloniaResource`） |

## 使用

```bash
python scripts/icons/generate_icons.py
```

依赖 Python 3 与 `pillow`、`numpy`。修改母版后重新执行即可，产物已提交进仓库。

## 关键约束

**不要手工制作 `.ico`。** 只放一个 32×32 帧进去，Windows 在任务栏、资源管理器、托盘里只能拉伸插值显示，图标必然模糊。多层 ico 是硬性要求。

保存 ICO 时**不要传 `append_images`** —— Pillow 会忽略 `sizes` 参数，产出只有一帧的 ico。正确写法是把大图直接交给 Pillow 并声明 `sizes`，由它逐层执行 `resize(size, LANCZOS)`。

**抠背景必须基于边界连通性。** 母版中央的白色文字与白色元素是设计的一部分；简单地"所有近白转透明"会在图形上打出破洞。脚本用从四边出发的 flood fill，只移除真正的外围背景。

**抠完背景必须给白卡片加圆角。** 本 logo 带一张铺满的白色卡片，flood fill 只会啃掉卡片外圈的背景，卡片本身（直角方块）会一直顶到画布边缘，肉眼看就是"内容贴边"。`apply_card_rounding` 把卡片四角切成透明，卡片与背景之间才有明确轮廓。

**处理顺序不能颠倒**：先抠背景 → 再切圆角 → 最后羽化。若先切圆角，四角变透明后 flood fill 会从这些新透明的角落向内扩散，误把白卡片边缘一起抠掉。

## 留白与圆角参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `PADDING_RATIO` | **0.0** | 四周透明留白占画布的比例。默认满出血 |
| `CARD_CORNER_RATIO` | 0.22 | 圆角矩形半径占边长的比例，接近 Apple 连续曲率观感 |

**为什么默认 0 留白（满出血）**：对标 ZCode 官方图标集（`zai-org/ZCode` 的 `packages/desktop/build/icons`），实测其 16/32/48/256/1024 各档**左边距均为 0px、内容占满 100% 画布**。此类应用图标靠**圆角切边**产生视觉留白，而不是真的留透明边。

曾尝试 10%~14% 留白（依据 macOS icns 内缩建议），在 Windows 任务栏和托盘里图标明显偏小——小尺寸下每一格像素都很宝贵，白色留白等于浪费。**不要把 macOS 的内缩规范直接套用到 Windows。**

如需改为带透明边，把 `PADDING_RATIO` 调大即可（分母是最终画布，不是内容边长）。注意留白与圆角叠加会产生"双重内缩"，视觉上更小。

## 已知限制

16×16 托盘图标仅有 256 个像素，母版的 "MARKET ASSISTANT" 文字缩到该尺寸后会糊成色块。满出血已把内容占比拉到最大，但若要托盘完全清晰，需单独设计一个只保留狐狸轮廓的简化版图标。
